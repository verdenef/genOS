# genOS Virtual Office — Hybrid Design Spec

**Date:** 2026-10-10
**Status:** Approved
**Approach:** Hybrid — Grok Bot runtime + genOS brain as single source of truth

---

## 1. Overview

The Virtual Office is a genOS integration that turns Grok Bot's cloud agent platform into a persistent, semi-autonomous development team for any genOS project. Each Agency Agent defined in `brain/60_AGENTS.md` maps to a dedicated Grok Bot. A dedicated **Lead Bot** coordinates daily work assignments. All state flows through the genOS Project Brain via git, preserving the single-source-of-truth guarantee.

### Core Principles

1. **genOS is the brain** — Grok Bots are workers, not memory holders. All durable state lives in `brain/`.
2. **Semi-autonomous with approval gates** — The Lead Bot proposes work, the human approves, then bots execute without interruption.
3. **Git-based sync** — Each bot operates on its own branch (`bot/<agent-name>`), pushes to GitHub, and the human merges via PR review.
4. **One office per project** — Each genOS project gets its own Grok Bot thread staffed by the agents listed in that project's `60_AGENTS.md`.

### Data Flow

1. **Lead Bot** reads `brain/50_ROADMAP.md` and `brain/40_BACKLOG.md` from `main` branch.
2. Lead Bot proposes daily work assignments to the human in the Grok Bot project thread.
3. Human approves the plan.
4. Lead Bot dispatches tasks to Builder/QA bots via Grok's inter-bot messaging.
5. Each bot clones the repo, creates its branch, implements work, commits, pushes.
6. QA Bot pulls Builder's branch to review and verify.
7. Bots post completion status in the project thread.
8. Human reviews PRs on GitHub, merges approved work to `main`.
9. genOS brain is updated. Obsidian Graph View reflects changes automatically.

## 3. Bot Roles

### Lead Bot (New Role — Coordinator)
- **Purpose:** Reads the genOS brain, proposes daily work assignments, dispatches tasks to other bots, and reports end-of-day summaries.
- **Can read:** All `brain/` files.
- **Can write:** `brain/20_PROGRESS.yaml` (session_summary only), status updates in project thread.
- **Cannot:** Write code, modify systems, or make architectural decisions.

### Builder Bots (Mapped from 60_AGENTS.md)
- **Purpose:** Implement code, assets, and configurations for assigned tasks.
- **Can read:** All `brain/` files, all source code.
- **Can write:** Source code, `brain/systems/*.md` (design updates), `brain/20_PROGRESS.yaml`.
- **Git branch:** `bot/<agent-name>` (e.g., `bot/unity-architect`).
- **Protocol:** Must follow genOS BOOT → Implement → SHUTDOWN cycle per task.

### QA Bot (Mapped from 60_AGENTS.md)
- **Purpose:** Review Builder output, run tests, verify acceptance criteria.
- **Can read:** All `brain/` files, all source code, Builder's branch.
- **Can write:** Review comments on PRs, test results, `brain/20_PROGRESS.yaml` (blockers).
- **Protocol:** Adversarial audit per `workflow-autonomous-batch.md` Phase 2 Step B.

## 4. Grok Bot Configuration

Each bot receives a **system prompt** generated by the setup prompt. The system prompt contains:

### Common Elements (All Bots)
```
You are a genOS agent working in a Virtual Office. Your project brain 
is the single source of truth. You must:

1. BOOT: Clone the repo (or pull latest main). Read AGENTS.md, then 
   brain/00_PROJECT.md, brain/20_PROGRESS.yaml, brain/50_ROADMAP.md.
2. WORK: Create branch bot/<your-name>. Implement your assigned task.
3. SHUTDOWN: Update brain files on your branch. Commit and push. 
   Run the Sanity Gate checks before pushing.
4. REPORT: Post a completion summary in the project thread.

Never store durable project state in your Grok memory. Always write 
it to the genOS brain files and commit to git.
```

### Role-Specific Elements
- Identity block from `60_AGENTS.md` (name, discipline, responsibilities)
- Scope limits (which files this bot can touch)
- Reference to relevant `brain/systems/*.md` for domain context

## 5. The Daily Cycle

### Morning Check-In (Human-Triggered)
1. Open Grok Bot app (phone, tablet, or desktop).
2. Message the Lead Bot: "What's on the agenda today?"
3. Lead Bot reads `main` branch → `50_ROADMAP.md` active milestone + `40_BACKLOG.md`.
4. Lead Bot proposes assignments:
   ```
   📋 Daily Plan — Baybayin Capstone
   
   Active Milestone: M6 — Combat System Polish
   
   Proposed Assignments:
   • unity-architect → Implement hitbox refinement (M6.2)
   • testing-reality-checker → Regression test M6.1 combat animations
   
   Approve to dispatch?
   ```
5. Human approves (or modifies) the plan.

### Autonomous Execution (Bots Work)
6. Lead Bot dispatches tasks to Builder and QA bots in the project thread.
7. Builder Bot clones repo, creates `bot/unity-architect` branch, implements task.
8. Builder Bot commits, pushes, and posts "Ready for review" in the thread.
9. QA Bot pulls Builder's branch, runs tests, posts findings.
10. If issues found: QA tags Builder in thread for fixes (2-retry budget, same as autonomous batch).
11. If clean: QA posts "Approved" in thread.

### Evening Review (Human Reviews)
12. Human checks GitHub for PRs from bot branches.
13. Reviews code changes and brain file updates.
14. Merges approved PRs to `main`.
15. Local repo pulls latest → Obsidian Graph View updates.

## 6. Inter-Agent Communication

Leverages Grok Bot's native multi-bot thread feature:

- **Project Thread:** One persistent Grok thread per project. All bots for that project participate.
- **Task Handoffs:** Builder tags QA when ready for review. QA tags Builder if fixes needed.
- **Lead Bot Coordination:** Lead Bot monitors thread, tracks which tasks are complete, and reports status.
- **Escalation:** If a bot hits a blocker it can't resolve after 2 retries, Lead Bot escalates to the human with a clear summary.

## 7. Setup Flow

### What the Human Does (Manual, in Grok Bot App)
1. Create a Lead Bot for the project (name: `[Project] Lead`).
2. Create one Grok Bot per Agency Agent in `60_AGENTS.md`.
3. Paste the generated system prompt into each bot's profile.
4. Create a shared project thread and add all bots to it.
5. Grant each bot access to the GitHub repo (via Grok Bot's GitHub integration).

### What the Setup Prompt Does (Automated, in Cursor/Antigravity)
1. Reads `brain/60_AGENTS.md` to enumerate the active workforce.
2. Reads `AGENTS.md` to extract the genOS protocol.
3. Generates a ready-to-paste system prompt for each bot (Lead + all agents).
4. Generates a "Teach a Task" script for the daily cycle.
5. Outputs everything in a clean, copy-paste-friendly format.

## 9. Constraints & Limitations

- **No Unity screenshot streaming** — Grok Bots run in the cloud, they cannot see your local Unity editor.
- **No custom dashboard** — You use Grok Bot's native app as the UI.
- **No local execution** — Bots run on Grok's cloud computers, not your laptop.
- **Git merge conflicts** — If two bots edit the same brain file, the human resolves conflicts during PR review.
- **Grok Bot API dependency** — If Grok changes their platform, the integration may need updates.

These limitations are addressed in the **Future Vision** spec (full "build from scratch" approach).

## 10. Success Criteria

1. A genOS user can set up a Virtual Office for their project in under 30 minutes.
2. The Lead Bot correctly reads and proposes tasks from the genOS brain.
3. Builder and QA bots follow the genOS BOOT/SHUTDOWN protocol via git branches.
4. All work is traceable via git history and PR reviews.
5. The genOS brain remains the single source of truth with zero state drift.
